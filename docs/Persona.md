# Persona.md

## 1. Persona Overview

### Persona
搬家 / 回国前需要处理大量家具的人

### Persona Type
Primary Persona

### Product
SnapList

### Product Concept
> **「部屋を一枚撮るだけで、全部売れる。」**

AI 识别并分类房间中的家具，自动生成商品清单。用户可以通过一个 URL 分享商品，并统一管理商品的出售状态。

## 2. Who is the User?

### 核心用户
即将搬家或回国，需要在有限时间内处理大量家具的人。

### 主要用户群体
- 学生
- 外国常住者
- 即将搬家的人
- 即将回国的人

### 用户当前状态
用户已经确定需要出售或处理家具，并开始实际整理房间。该行为通常发生在搬家或回国日期已经确定之后，因此具有明确的时间限制。

## 3. User Context

### 发生时间
确定搬家 / 回国之后，到正式搬离之前。

### 典型场景
用户开始整理自己的房间，发现有大量家具和闲置物品需要处理，例如桌子、椅子、柜子、台灯、家电及其他生活用品。

### 场景特点
- 时间紧迫
- 一次需要处理的物品数量较多
- 需要在搬家前完成处理
- 可能同时使用多个渠道寻找买家

## 4. User Problems

### Problem 01：时间紧迫
搬家或回国日期已经确定，用户需要在有限时间内处理大量物品。

**用户感受：**“马上要搬家了，还有很多东西没有处理。”

### Problem 02：商品数量太多
用户需要逐件确认哪些家具需要出售，并分别整理。当商品数量增加后，整理本身就成为明显的负担。

**用户感受：**“东西太多了，不知道从哪里开始。”

### Problem 03：整理和出品流程繁琐
目前用户需要针对每件商品分别确认、拍照、填写商品名称、编写说明、决定价格并发布商品。当一次需要处理大量商品时，相同操作会不断重复。

**用户感受：**“一个个拍、一个个写太麻烦了。”

### Problem 04：出售状态更新耗时
用户可能通过 SNS、校友群、ジモティー、Mercari 等不同渠道寻找买家。随着商品数量增加，很难快速掌握哪些还在出售、哪些已经有人预约、哪些已经售出。

**用户感受：**“这个到底卖掉了吗？”“还要去其他地方更新状态吗？”

## 5. Current Solutions

用户目前主要使用：
- SNS
- 校友群
- ジモティー
- Mercari

### 当前流程
整理房间 → 逐件确认需要出售的家具 → 逐件拍照 → 编辑商品名称、说明和价格 → 发布到二手平台 / SNS / 校友群 → 等待并回复买家 → 手动更新每件商品的出售状态

## 6. Pain Points of Current Solutions

1. **以单个商品为单位**：需要一次处理大量家具时，不断重复相同操作。
2. **手动输入较多**：商品名称、说明、价格等信息需要逐件填写。
3. **多渠道管理复杂**：用户需要自己记住每件商品的当前状态。
4. **缺少整体视角**：难以快速知道总商品数、出售中、已预约和已售出的数量。

## 7. User Goals

### Primary Goal
**在搬家或回国之前，用尽可能简单、快速的方式出售和处理不再需要的家具。**

### Goal 01：简单地出售家具
减少整理、拍照、填写商品信息等重复操作。理想体验是：**一次拍摄房间，就可以开始整理多个商品。**

### Goal 02：实时掌握家具状态
用户希望随时知道哪些商品处于出售中、已预约、已售出状态，从而减少反复确认和更新的负担。

## 8. User Needs

- **批量整理**：一次处理多个商品，而不是逐件开始新的出品流程。
- **减少手动输入**：商品识别、分类和基本商品信息尽可能自动生成。
- **快速确认 AI 结果**：AI 自动整理 → 用户快速确认 / 修改。
- **统一管理出售状态**：通过一个界面掌握所有商品的当前状态。
- **简单分享多个商品**：一次分享多个商品，而不是逐件发送商品信息。

## 9. Behavioral Characteristics

- **Task-oriented**：目标是尽快完成家具处理任务。
- **Time-sensitive**：存在明确的搬家 / 回国期限。
- **Low tolerance for repetitive work**：不希望进行大量重复输入。
- **Needs control over AI**：需要能够确认、编辑、删除和补充 AI 结果。

## 10. Core User Scenario

确定搬家 / 回国 → 发现大量家具需要出售 → 打开 SnapList → 拍摄一张房间照片 → AI 识别并分类多个家具 → 用户确认需要出售的商品 → AI 自动生成商品信息 → 用户确认 / 修改 → 生成统一商品清单 → 通过一个 URL 分享商品 → 买家联系 → 用户更新 Available / Reserved / Sold 状态 → 随时确认尚未处理的家具 → 在搬家前完成家具处理。

## 11. Expected User Experience

- **Before**：“东西这么多，一个个整理太麻烦了。”
- **After AI Detection**：“一张照片就把要处理的东西整理出来了。”
- **After AI Generation**：“不用每个商品都从头填写了。”
- **During Selling**：“现在一眼就能知道哪些已经卖掉了。”
- **Final**：“搬家前终于把这些东西处理完了。”

## 12. Implications for Product & UI Design

1. **One Photo → Multiple Items**：突出一次拍摄同时处理多个商品。
2. **AI reduces repetitive work**：AI 负责商品识别、分类和信息生成。
3. **Human-in-the-loop**：AI 结果允许确认、修改和删除。
4. **Centralized Management**：从整体列表掌握所有家具状态。
5. **Easy Sharing**：降低向 SNS、校友群等渠道分享多个商品的成本。
6. **Home**：核心 CTA 为拍摄 / 上传房间照片。
7. **AI Processing**：明确显示 AI 正在分析什么和当前处理状态。
8. **Detection Result**：支持查看、选择、删除和补充识别商品。
9. **Listing**：以 Card 形式展示商品信息。
10. **Dashboard**：突出全部商品、Available、Reserved、Sold 及整体处理进度。

## 13. Product Opportunities

1. 房间照片 → AI 批量识别多个商品
2. AI 自动生成商品信息
3. 统一管理商品出售状态
4. 一个 URL 分享多个商品

## 14. Open Questions

### 【需要确认 01】用户年龄与具体生活阶段
目前只确定主要用户包括学生、外国常住者以及搬家 / 回国人群。

### 【需要确认 02】处理速度与出售价格的优先级
需要进一步确认用户更重视尽可能卖出高价，还是在搬家期限前尽快处理完。

### 【需要确认 03】主要销售渠道
目前包括 SNS、校友群、ジモティー、Mercari，但尚未确定主要渠道。

### 【需要确认 04】产品处理范围
需要进一步确认 SnapList 是家具专用工具，还是扩展为搬家闲置物品整理工具。

### 【需要确认 05】一个 URL 的使用方式
需要验证 URL 主要分享给 SNS、校友群、朋友还是潜在买家，以及买家是否需要在页面直接预约或联系。

## 15. Persona Summary

- **Who**：即将搬家或回国，需要一次处理大量家具的人。
- **Situation**：时间有限、需要处理的商品数量较多。
- **Current Solution**：SNS / 校友群 / ジモティー / Mercari。
- **Core Pain**：逐件整理、编辑商品信息以及持续更新出售状态非常耗时。
- **Goal**：简单快速地出售家具，并实时掌握所有家具的出售状态。
- **Core Product Opportunity**：一张房间照片 → AI 批量识别 → 自动生成商品信息 → 一个 URL 分享 → 集中管理出售状态。
