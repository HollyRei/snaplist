# product.md

## 1. 产品概述 Product Overview

### 产品名称
SnapList

### Product Concept
> **「部屋を一枚撮るだけで、全部売れる。」**

### 一句话介绍
帮助即将搬家或回国的用户，通过 AI 批量识别闲置家具、自动生成出售信息，并集中管理商品出售状态的工具。

### 核心问题
用户真正的问题不是“没有地方出售二手家具”，而是：**在搬家或回国前时间有限的情况下，需要快速整理和出售大量物品，而现有方式需要逐件处理，操作繁琐且难以统一管理。**

### 核心价值
将“逐件确认 → 逐件拍照 → 逐件填写 → 逐件管理”转变为“批量识别 → AI 自动生成 → 用户确认 → 集中管理”。

## 2. Target User

### 核心用户
近期准备搬家或回国，并需要一次性处理大量家具和闲置物品的人。

### 主要用户群体
- 学生
- 外国常住者
- 即将搬家的人
- 即将回国的人

### 使用场景
用户确定搬家或回国后，在有限时间内整理房间、出售家具，并持续跟踪每件商品的状态。

### 当前解决方式
Mercari、ジモティー、SNS、校友群、手机拍照及备忘录等。

## 3. User Problems

### Problem 01：大量物品整理耗时
大量物品需要逐个确认、整理，非常耗时。

### Problem 02：商品信息需要重复编辑
每件商品都要分别拍照、填写名称和说明、决定价格。

### Problem 03：出售状态难以统一管理
商品较多、渠道较多时，很难掌握哪些出售中、已预约或已售出。

### Future Problem：多渠道重复发布
同样的信息需要重复发布到不同平台。

### Future Problem：未售商品处理
临近搬家时，未售出的商品需要重新决定降价、赠送、回收或废弃。

## 4. MVP Features

本次 MVP 以 3 个核心功能为中心。

### MVP 01 — AI 批量识别商品

**对应问题**：大量商品需要逐件确认和登记。

**功能说明**：用户上传或拍摄一张包含多个家具的房间照片，AI 一次识别多个可能出售的物品。

**用户操作**：
1. 上传 / 拍摄房间照片
2. 等待 AI 分析
3. 查看识别结果
4. 选择需要出售的商品
5. 删除错误识别或补充遗漏商品
6. 确认

**Frontend**：
- 图片上传 / 拍摄
- 图片预览
- AI Processing 状态
- 商品识别结果
- 商品选择 / 删除 / 添加
- 确认按钮

**Backend**：
- 接收图片
- AI 图像分析
- 多物品识别
- 返回结构化商品数据

**MVP 范围**：识别商品大类别即可，不要求准确识别品牌和型号。

### MVP 02 — AI 自动生成商品信息

**对应问题**：商品名称、说明和价格需要逐件填写。

**功能说明**：根据识别结果，为每件商品自动生成基本出售信息。

**生成内容**：
- 商品名称
- 商品类别
- 商品介绍
- AI 建议价格

**用户操作**：
1. 选择识别商品
2. AI 生成商品信息
3. 查看结果
4. 修改不准确内容
5. 保存商品

**Frontend**：
- 商品 Card
- 商品图片
- 商品名称 / 类别 / 说明
- AI 建议价格
- 编辑 / 保存

**Backend**：
- 商品名称生成
- 商品说明生成
- 建议价格生成
- 商品信息保存

**MVP 范围**：价格明确标记为“AI 建议价格”，不要求真实市场估价完全准确。

### MVP 03 — 统一管理商品出售状态

**对应问题**：大量商品的预约和出售状态难以管理。

**功能说明**：所有商品集中显示在一个页面，并使用统一状态进行管理。

**状态**：
- Available / 出售中
- Reserved / 已预约
- Sold / 已售出

**用户操作**：
1. 查看全部商品
2. 查看当前状态
3. 修改状态
4. 按状态筛选
5. 编辑商品信息

**Frontend**：
- 商品列表
- 商品 Card
- 状态标签
- 状态切换
- 状态筛选
- 数量 Summary

**Backend**：
- 保存商品数据
- 保存商品状态
- 更新商品状态
- 根据状态读取商品列表

**MVP 范围**：只管理 SnapList 内部状态，不与外部平台实时同步。

## 5. Core User Flow

进入 SnapList → 上传 / 拍摄房间照片 → AI 分析 → 显示多个识别商品 → 用户选择需要出售的商品 → AI 自动生成商品名称、介绍和建议价格 → 用户确认 / 编辑 → 保存到商品列表 → Dashboard 查看全部商品 → 更新 Available / Reserved / Sold 状态。

## 9. Future Features

### Future 01 — 一个 URL 分享商品
将多个商品生成统一的 Moving Sale 页面，通过 SNS、校友群、朋友等渠道分享。

### Future 02 — 多平台文案生成
针对 Mercari、ジモティー、SNS 等渠道自动调整商品文案。

### Future 03 — 卖 / 送 / 丢智能建议
根据剩余搬家时间、商品价值和状态推荐出售、赠送或处理。

### Future 04 — 外部平台状态同步
未来与二手交易平台同步商品状态。

### Future 05 — AR 家具预览
让购买者通过 AR 确认大型家具在自己房间中的尺寸和空间效果。

## 10. MVP Validation

重点验证：
1. 一张照片识别多个商品是否比逐件登记更轻松。
2. AI 自动生成商品信息是否减少编辑时间。
3. 用户是否能够理解并使用统一的出售状态管理。
4. “上传 → AI 识别 → AI 生成 → 确认 → 管理”的 Core Flow 是否足够简单。

## 11. Open Questions

- 【需要确认】AI 建议价格未来是否基于真实二手市场数据。
- 【需要确认】正式产品是否需要账户 / 登录系统。
- 【需要确认】识别商品后的图片采用原图裁切、用户重新拍摄还是其他方式。
- 【需要确认】Mercari、ジモティー、SNS、校友群中哪个是主要销售渠道。
- 【需要确认】产品最终范围是家具，还是所有搬家闲置物品。

## 12. Product & UI Principles

1. 优先解决“数量多、时间少”的核心问题。
2. 强调 **One Photo → Multiple Items**。
3. 尽量减少逐件重复操作和文字输入。
4. AI 是助手，所有结果允许用户确认和修改。
5. UI 清晰展示 AI 当前处理状态。
6. Dashboard 强调商品整体处理进度。
7. MVP 只围绕 AI 批量识别、AI 商品信息生成、出售状态统一管理三个核心功能。
8. 一个 URL 分享、多平台发布、智能处理建议和 AR 等功能保留为 Future Features。
